# 通过 Agent 安排和开始复习

当前插件支持用户指定日期、Agent查询队列和记录再次作答。它不会在后台弹出提醒，也没有自动间隔算法。

## 安排一题

可以说：“把这道已经纳入的题安排在北京时间2026年9月26日上午9点复习。”

Agent先读取题目与计划版本，再调用update_review_plan，日期为2026-09-26T09:00:00+08:00。原题使用original；变式使用exercise并指定下标，且答案须检查通过。相对日期应根据用户当前日期和时区解释；缺少会影响安排的时刻或时区时需澄清，不能静默替用户选择。改版后的旧计划需要重新核对，不会自动挪到新题面。

## 查询哪些题该做

| 用户意图 | 当前调用方式与含义 |
| --- | --- |
| 现在有哪些到期题 | read_review_queue默认due，省略as_of，包含仍有效的逾期计划 |
| 到某个时刻一共有哪些待复习题 | due配合含时区的as_of；截止时刻本身算到期，也包含更早逾期题 |
| 只看明天安排的题 | 先分页读取scheduled，再由Agent按用户当地日期筛选due_at；不能把“明天结束前到期”当成“只安排在明天” |
| 查看未来及尚未完成的安排 | status=scheduled，包含未来计划；is_due依查询截止时刻计算 |
| 找出题目修订后需要重排的计划 | status=outdated，回读当前题目和旧安排再处理 |
| 核对某题以前如何改期或取消 | read_review_plan并按next_before_revision翻页，读取保存的历史 |

队列按实际到期时刻排序；同时刻按记录ID排序，不代表学习优先级。分页时复用首次返回的as_of，可固定时间截止点；仍不保证跨页数据库快照，计划发生变化应重新从首页查询。

as_of不是“回到过去”：队列始终使用当前最新计划。取消后，传入取消前的时间也不会重新显示旧计划；历史应从read_review_plan核对。完成表示已关联一次新作答，不等于答对、独立完成或掌握。

## 开始答题

题面来自识别结果且有冲突时，先按[原图核对指南](ocr-conflict-user-guide.md)确认题意。识别失败与学生答错分别处理；题面尚不能确认时，不能用它判断学习效果。

可以说：“从到期队列开始第一题，先只给题目，等我回答。”

Agent用队列里的record_id、current_record_revision和原题/变式目标调用read_practice_prompt，无需先展示完整错题记录。默认队列省略可能泄露答案的原标签；题面本身仍需要核对是否含提示。原题text只是转录文本，需要配图时使用已复核净题图，不能以含原答案的证据图代替。

用户作答后才保存record_practice，帮助情况不明时标为unknown。用户明确完成本次复习时，再关联安排后同题、同版本、同目标的新作答完成计划。查询和取题都不会自动完成计划。

## 答错、要提示和看解析以后怎么继续

可以直接说：“先让我自己做；卡住时给一个提示，做完后指出具体错在哪一步。”想先学方法时，也可以说：“先讲一个例题，再让我做一题。”两种方式都可以用于学习，记录时要区分是否借助了帮助。例题学习和自己解题交替进行有研究依据，但不说明任何单次练习已经达到掌握。[IES 学习实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)

| 这次实际发生了什么 | 如何记录和解释 |
| --- | --- |
| 自己先做，做错了 | 已知未用帮助时记录independent；指出具体步骤，不抹掉原答案，也不把错误当成不该继续练习 |
| 得到提示后改对 | 新的一次作答记录hinted；可以说“这次在提示后改对了”，不能回写为之前独立做对 |
| 看过完整解析后再写 | 记录solution_seen；此时可让用户解释某一步为何成立，但复述不能当成未见答案的独立检验 |
| 后来另一次不借助帮助做对 | 有明确依据时记录independent；结合当时题面、间隔、是否做过同题解释进步，不能仅凭记录标签证明长期掌握 |
| 不清楚是否看过提示或答案 | 记录unknown；不要由答案正确推断independent |

Agent在收到真实作答后，先核对该次题目快照及参考答案，再给出具体反馈和下一步。反馈可以指出对错，但还应解释关键步骤。反馈记录与原作答分开保存；用户没有表达自己的对错判断时，不能代填用户确认。作答后提供反馈是检索练习实践中的重要环节。[RetrievalPractice.org 反馈说明](https://www.retrievalpractice.org/feedback)

例如针对分配律，可以在用户作答后追问：“括号外的数分别乘了哪两项？”这是教学提问示例，不是自动测得的错因。用户请求提示或解析时正常提供，并如实记录帮助情况；需要检查能否独立完成时，另选尚未显示答案、题意相近且已检查答案的题目，或在用户指定日期重新练习。不要强制套用固定间隔，也不要把同题紧接着答对称作延迟复测。

对进步的表达以证据为限，例如：“第一次独立作答漏乘了常数项，第二次在提示后改对；还没有稍后独立复测的结果。”研究中自信提升与成绩提升并不总是一致：一项大学生物课程AI反馈研究的摘要报告，各反馈类型间未观察到显著成绩差异，同时学生报告了反思行为变化。它不能用于证明本插件或初中数学练习有效。[研究摘要，2025](https://arxiv.org/abs/2505.13381)

第78轮用安装版完成37次MCP调用，以5次明确标注的合成作答核对四类帮助情况、反馈、重复提交、分页和重启后的历史；后续作答没有改写早先提示后完成的计划。合成响应不是学生数据，没有真实教学对话、延迟复测或效果结论。本轮验证结果（本地历史证据未公开）

## 时区与验证范围

日期保存的是带数值偏移的具体时刻。例如2026-09-26T00:15:00+14:00比2026-09-25T23:30:00+08:00更早。回拨时两个01:30可由-04:00和-05:00区分，相差一小时。工具不会根据城市名自动选择偏移，也没有“每周当地9点”的重复计划规则。

第71轮在已安装版本上用6个合成计划完成42次MCP调用，覆盖10个截止时刻、分页、取消历史和重启读取；4次无效日期请求被拒绝，查询前后数据行一致。临时工作区已清除，没有OCR调用。这不是实际学生学习效果、自动提醒或完整时区数据库验证。验证记录（本地历史证据未公开）
